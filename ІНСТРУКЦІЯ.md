## 1. Встановлення GitHub CLI

### Чому не winget?

На **Windows 10 LTSC 2019** команда `winget` недоступна за замовчуванням.  
Тому встановлюємо вручну через `.msi`-пакет.

### Кроки встановлення

**Крок 1.** Відкрийте браузер та перейдіть на сторінку релізів GitHub CLI:

```
https://github.com/cli/cli/releases/latest
```

**Крок 2.** Знайдіть файл `gh_X.XX.X_windows_amd64.msi` та завантажте його.

> У нашому випадку це був файл `gh_2.92.0_windows_amd64.msi`

**Крок 3.** Запустіть скачаний `.msi` файл та пройдіть установку (Next → Next → Install).

**Крок 4.** Перевірте встановлення — відкрийте нове вікно CMD та введіть:

```cmd
"C:\Program Files\GitHub CLI\gh.exe" --version
```

Очікуваний результат:
```
gh version 2.92.0 (2025-XX-XX)
```

## 2. Авторизація в GitHub CLI

### Отримання токена GitHub

**Крок 1.** Перейдіть на сайт GitHub та увійдіть у свій акаунт.

**Крок 2.** Перейдіть до налаштувань токенів:
```
GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
```

**Крок 3.** Натисніть **Generate new token (classic)**.

**Крок 4.** Налаштуйте токен:
- **Note:** `gh-cli-auth` (або будь-яка назва)
- **Expiration:** 90 days (або No expiration для тестів)
- **Scopes:** поставте галочки на:
  - `repo` (повний доступ до репозиторіїв)
  - `workflow` (для GitHub Actions)
  - `read:org` (читання організацій)

**Крок 5.** Натисніть **Generate token** та **одразу скопіюйте** токен — він показується лише один раз!

> Токен виглядає так: `ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`

### Авторизація через CMD

**Крок 1.** Відкрийте **CMD** (не PowerShell, не термінал Claude Code).

**Крок 2.** Виконайте команду — вставте свій токен замість `ВАШ_ТОКЕН`:

```cmd
echo ВАШ_ТОКЕН | "C:\Program Files\GitHub CLI\gh.exe" auth login --with-token
```

**Крок 3.** Якщо команда виконалась без помилок (просто повернувся рядок `C:\...>`), авторизація пройшла успішно.

**Крок 4.** Перевірте авторизацію:

```cmd
"C:\Program Files\GitHub CLI\gh.exe" auth status
```

Очікуваний результат:
```
github.com
  ✓ Logged in to github.com account ВАШ_ЛОГІН (keyring)
  - Active account: true
  - Git operations protocol: https
  - Token: ghp_****
  - Token scopes: 'gist', 'read:org', 'repo', 'workflow'
```

> **ВАЖЛИВО:** Токен — це як пароль. Нікому не надсилайте його, не вставляйте в чат.  
> Якщо токен випадково потрапив у чат — негайно скасуйте його на github.com/settings/tokens

## 3. Створення репозиторію

Відкрийте термінал Claude Code (або CMD) та виконайте:

```
"C:\Program Files\GitHub CLI\gh.exe" repo create test-claude-integration --public --add-readme
```

Або прямо в чаті Claude Code з `!` на початку:

```
! "C:\Program Files\GitHub CLI\gh.exe" repo create test-claude-integration --public --add-readme
```

Очікуваний результат:
```
✓ Created repository ВАШ_ЛОГІН/test-claude-integration on GitHub
  https://github.com/ВАШ_ЛОГІН/test-claude-integration
```

## 5. Встановлення Claude GitHub App

Це ключовий крок — саме він дозволяє Claude автоматично реагувати на коментарі та Pull Request'и.

### Запуск команди

В терміналі Claude Code введіть:

```
/install-github-app
```

### Покрокова авторизація

**Крок 1.** Оберіть репозиторій зі списку (стрілками + Enter):
```
? Select a repository to install the GitHub App on:
> ВАШ_ЛОГІН/test-claude-integration
```

**Крок 2.** Оберіть тип підписки:
```
? Do you have a Claude.ai subscription?
> Yes, I have a Claude.ai subscription
```

**Крок 3.** Скопіюйте довгу URL-адресу, яку видасть термінал, та відкрийте її у браузері вручну.  
URL виглядає приблизно так:
```
https://github.com/apps/claude/installations/new?...
```

**Крок 4.** У браузері з'явиться сторінка авторизації Claude.  
Натисніть **"Allow"** або **"Authorize Claude"**.

**Крок 5.** Після авторизації браузер покаже **довгий код** (authorization code).  
Скопіюйте його та вставте в термінал Claude Code.

**Крок 6.** Дочекайтеся повідомлення про успіх:
```
✓ GitHub Actions workflow created!
✓ API key saved as CLAUDE_CODE_OAUTH_TOKEN secret
```

### Що створилось автоматично?

Після встановлення у репозиторії з'явились два файли:

**`.github/workflows/claude.yml`** — реагує на `@claude` у коментарях до Issues та PR:
```yaml
on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]
```

**`.github/workflows/claude-code-review.yml`** — запускає Code Review на кожен Pull Request:
```yaml
on:
  pull_request:
    types: [opened, synchronize, reopened]
```

А також у **Settings → Secrets → Actions** з'явився секрет:
- `CLAUDE_CODE_OAUTH_TOKEN` — токен для авторизації Claude у GitHub Actions

## 6. Тест 1 — @claude у Issues

### Створення тестового Issue

**Крок 1.** Відкрийте репозиторій на GitHub.

**Крок 2.** Перейдіть до розділу **Issues** → натисніть **New issue**.

**Крок 3.** Заповніть:
- **Title:** `Тест: додай привітання`
- **Description:** будь-який текст, наприклад `Перевіряємо інтеграцію з Claude`

**Крок 4.** Натисніть **Submit new issue**.

### Виклик Claude через @claude

**Крок 1.** У відкритому Issue, внизу в полі коментаря напишіть:

```
@claude додай у README.md рядок "Hello from Claude!"
```

**Крок 2.** Натисніть **Comment**.

### Що відбувається далі

- GitHub Actions автоматично запускає workflow `claude.yml`
- Claude отримує завдання та виконує його у репозиторії
- Claude сам створює Pull Request зі змінами
- В Issue з'являється коментар-відповідь від Claude з посиланням на PR

**Реальний результат:** Claude виконав завдання за **43 секунди** та залишив коментар:
```
I've added "Hello from Claude!" to the README.md file. 
You can review the changes in Pull Request #2.
```

### Злиття Pull Request від Claude

Після того як Claude створив PR, злийте його:

```
! "C:\Program Files\GitHub CLI\gh.exe" pr merge 2 --merge --repo ВАШ_ЛОГІН/test-claude-integration
```

## 7. Тест 2 — Автоматичний Code Review

### Створення тестового Pull Request

**Крок 1.** Внесіть будь-яку зміну в репозиторій та надішліть як PR.  
Можна зробити це через API:

```
! "C:\Program Files\GitHub CLI\gh.exe" api repos/ВАШ_ЛОГІН/test-claude-integration/contents/test.py \
  --method PUT \
  --field message="Add test file for code review" \
  --field content="$(python -c "import base64; print(base64.b64encode(b'def hello():\n    print(\"Hello World\")\n').decode())")" \
  --field branch="feature/test-review"
```

Або просто відредагуйте будь-який файл через інтерфейс GitHub і збережіть у новій гілці.

**Крок 2.** Створіть Pull Request:

```
! "C:\Program Files\GitHub CLI\gh.exe" pr create \
  --repo ВАШ_ЛОГІН/test-claude-integration \
  --title "Test: code review" \
  --body "Тестуємо автоматичний Code Review від Claude" \
  --head feature/test-review \
  --base main
```

### Що відбувається автоматично

Як тільки PR створено:
- GitHub Actions запускає `claude-code-review.yml`
- Claude аналізує всі зміни в PR
- Claude залишає детальний коментар прямо в Pull Request

**Реальний результат:** Claude виконав Code Review за **1 хвилину 37 секунд**.  
Коментар містив:
- Загальну оцінку змін
- Конкретні зауваження по рядках коду
- Пропозиції щодо покращення
- Відмітку про успішне проходження перевірки

### Злиття Pull Request

```
! "C:\Program Files\GitHub CLI\gh.exe" pr merge 4 --merge --repo ВАШ_ЛОГІН/test-claude-integration
```

## 8. Результати та що це дає

### Переваги для розробника

| Можливість | Без Claude | З Claude |
|-----------|-----------|----------|
| Відповідь на Issue | Вручну, годинами | Автоматично, ~1 хв |
| Code Review | Чекати колегу | Миттєво при кожному PR |
| Документація | Писати вручну | @claude напиши README |
| Рефакторинг | Самостійно | @claude переписати функцію |
| Пошук помилок | Вручну | @claude знайди баги |

### Команди, які розуміє @claude

- `@claude додай коментарі до коду`
- `@claude напиши unit-тести`
- `@claude виправ помилку у рядку 42`
- `@claude поясни цю функцію`
- `@claude оптимізуй цей цикл`
- `@claude додай обробку помилок`


## 9. Безпека та важливі правила

### Правило №1 — Токени є паролями

**Ніколи** не вставляйте токени (`ghp_...`), паролі або секрети:
- в чат (будь-який — Claude Code, Telegram, email)
- в код репозиторію (особливо публічного)
- в коментарі до Issues або PR

Якщо токен випадково опинився у відкритому місці — **негайно скасуйте його**:
```
github.com → Settings → Developer settings → Personal access tokens → Delete
```

### Правило №2 — Секрети зберігайте в GitHub Secrets

Правильне місце для токенів і ключів:
```
Репозиторій → Settings → Secrets and variables → Actions → New repository secret
```

Claude Code автоматично зберіг `CLAUDE_CODE_OAUTH_TOKEN` саме туди.

### Правило №3 — Перевіряйте що робить Claude

Перед тим як зливати PR від Claude:
1. Відкрийте PR та перегляньте список змінених файлів
2. Подивіться на конкретні зміни (вкладка "Files changed")
3. Переконайтесь, що Claude зробив саме те, що просили

### Де знаходяться логи

Переглянути роботу GitHub Actions:
```
Репозиторій → Actions → (обрати workflow) → (обрати запуск) → (обрати job)
```
